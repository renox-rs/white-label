# edtech

The vertical app for training and tutoring centres
([spec](../../docs/verticals/10-edtech.md)): courses and programmes, the
batches that run them, the sessions generated from a batch's weekly plan,
enrolments with their seats and fees, attendance and certificates. The app
reaches the other modules only through the contracts of `wl-kernel` (the
scheduling events and availability, the qualification and document guards, the
notifier, the task creator, the invoicer), never through their crates.

The host mounts it when `client.toml` names `app = "edtech"`:

```
use renox::prelude::*;

# let _ =
App::new().module(edtech::EdTech)
# ;
```

## Host wiring

The host (`host/src/lib.rs`) mounts `edtech::EdTech` for `app = "edtech"` and sets what the shared modules take for this client:

| File | What it sets |
|---|---|
| `host/src/app/edtech_seed.rs` | the document kinds with their `blocks`, override modes, look-ahead windows and responsible roles; the scheduling numbers (D = 30, H = 2, reminders 24 and 2 hours); the HR line manager; the service types and ticket categories (`edtech:install`) |
| `host/src/app/edtech_settings.rs` | the owner alert of `DOC.RUL.03`; the connections and their fallbacks; the notification, sales and loyalty values; the lead sources, send windows, loyalty programme, checklists, SOPs and notification reactions; the rows of `/settings/compliance`; the grants of the owner and the centre manager in this deployment |
| `host/src/app/edtech_money.rs` | the invoicing and payments values, the *Tutor costs* budget category and the rows of `/settings/negative-flow` |
| `clients/demo-edtech/client.toml` | the demo centre: modules parties, documents, notify, invoicing, ticketing, payments, sales, hr, attendance, scheduling and portal; branding; the public holidays |
| `host/src/app/roles.rs` | the roles `centre_manager`, `counsellor`, `academic_coordinator` and `tutor`, and the grants of owner, accountant and admin |

## Tests

`apps/edtech/tests/edu_NN_*.rs` hold the Done-when points of each issue (`BL-EDU-NN`, #435 + NN) against the app with the real wl-scheduling and wl-hr and stand-ins for the contracts of the other modules (`tests/support`); `edu_base_*.rs` cover the base lifecycles. `host/tests/edtech_wiring.rs`, `edtech_settings.rs` and `edtech_money.rs` prove the host: the roles, the document kinds, the settings and the money values through the booted demo centre with the real shared modules.
